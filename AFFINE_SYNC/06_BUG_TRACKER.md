# Bug Tracker

## BUG-001
| Field | Value |
|---|---|
| Module | Auto Layout / Build AI Draft |
| Description | Hero photo renders in an incorrect position (and, on further investigation, sometimes as the wrong photo entirely) on multi-page drafts generated by `buildAIDraft()` |
| Severity | High — affects core Auto Layout workflow output |
| Status | **FIXED** — verified via live browser test |
| Reproduction steps | 1. Upload multiple photos (10+ recommended, so overflow spans two content pages). 2. Let Hero Analysis produce a recommendation. 3. Click "Build AI Draft" to generate a multi-page project. 4. Navigate to page 3. 5. Hero photo position/identity did not match the page's intended photo/frame. |
| Root cause | Two compounding defects in `buildAIDraft()` → `renderComposition()` → `serializeActivePage()` (all in OCF_START.html): **(1) Geometry timing race** — `clearSlot('heroLayer')` reset `hero.{x,y,w,h}` to the `{0,0,420,522}` default on every `renderComposition()` call; the real cover-fit was only ever computed asynchronously inside `heroImg.onload`, which never fires within `buildAIDraft()`'s fully-synchronous page loop, so `serializeActivePage()` always captured the stale default instead of the true fit. **(2) Wrong hero identity** — `serializeActivePage()` reads `heroPhotoId` from the global `heroIndex`, which was only set once (via `setHero()`) before the loop started and never updated per page, so every generated page recorded the same `heroPhotoId` (the original recommended hero) regardless of which photo the layout plan actually assigned. This matches diagnostic categories (2)/(3) from the original four-way split — confirmed. |
| Fix commit | `3decadb5ddd5f0929bb80479b808aafadc8d78e1` |
| Retest result | PASS — see `AFFINE_SYNC/05_TEST_RESULTS.md` |
